# A command line for your stacks

`cfn_typed.cli` is an optional command line that you call from your own `main()`. It is not a
`cfn-typed` command: your script says which stacks exist, and the library gives them four
subcommands, `emit`, `check`, `diff` and `ls`. Nothing else in the package imports it, and it needs
nothing beyond the standard library (`-f yaml` needs `cfn-typed[yaml]`).

```python
# stacks.py
import sys
from functools import partial

import cfn_types  # generated by cfn-typegen
from cfn_typed import cli
from minimal import build


def main() -> int:
    return cli.main(
        {"orders-prod": partial(build, "prod"), "orders-dev": partial(build, "dev")},
        schemas=cfn_types,  # optional: turns on the checks against the registry schemas
        # rules=[my_rule],  # optional: your own checks, see "Company rules"
    )


if __name__ == "__main__":
    sys.exit(main())
```

The first argument is one builder (a function that returns the template) or a mapping from stack
name to builder. `cli.main` returns the exit status instead of exiting, so your `main()` decides what
to do with it. Every subcommand takes stack names and uses all of them when you give none.

## Without any Python: `cfn-typed`

The same subcommands work on template files, so the command line is useful for a template that
`cfn-typed` did not write. Install the package (`uv tool install 'cfn-typed[yaml]'`, or
`uvx --from 'cfn-typed[yaml]' cfn-typed ...`, or `python -m cfn_typed.cli`) and give it files, JSON
or YAML with the short-form intrinsics (`!Ref`, `!GetAtt A.Arn`, `!Sub`, ...):

```text
$ cfn-typed check template.yaml other.json
template: ok
other: ok
$ cfn-typed ls template.yaml -t lambda
$ cfn-typed emit template.yaml -f json        # convert YAML to JSON, or the other way round
$ cfn-typed diff rendered/ template.yaml      # compare with rendered/template.yaml
```

A stack is named after its file without the suffix, and two files with the same name are an
error. YAML needs PyYAML (the `yaml` extra); JSON needs nothing. Without generated types the
schema checks are off, and `--schemas cfn_types` (for `check`) turns them on from a package that
`cfn-typegen` generated, imported from the current directory. To add your own rules, write the
`main()` above instead.

## `emit`: print or write templates

```text
$ python stacks.py emit orders-dev
AWSTemplateFormatVersion: '2010-09-09'
Resources:
  Jobs:
    Type: AWS::SQS::Queue
    ...
```

`-f json|yaml` picks the format (YAML by default, or the suffix of `-o`). With several stacks you
have to name one, or write them all: `-o rendered/` creates `rendered/orders-prod.yaml`,
`rendered/orders-dev.yaml`, and `-o template.json` writes one stack to a file.

## `check`: run every check

```text
$ python stacks.py check
orders-prod: ok
orders-dev: ok
```

This is [`find_all_problems`](patterns/company-rules.md) for each stack: references, unused
parameters, quotas, values, IAM names and Lambda runtimes, and with `schemas=` the constraints,
`Fn::GetAtt` names and property combinations too. A problem is printed as `[check] message`, and
the exit status is 1 if any stack has one, so it works as a CI step. `--inline` applies the
51,200-byte inline limit, `--no-unused` and `--no-defaults` leave those checks out.

## `diff`: compare with the committed files

```text
$ python stacks.py diff rendered/
orders-prod: matches rendered/orders-prod.yaml
--- rendered/orders-dev.yaml
+++ rendered
@@ -10,4 +10,3 @@
 Outputs:
   JobsUrl:
     Value: !Ref Jobs
-x
```

It compares each stack with `DIR/<name>.yaml` (`-f json` for JSON), prints a unified diff and exits 1
on a difference or a missing file. `--update` rewrites the files instead. This is the
[golden-file workflow](testing.md) without pytest, for a repository that wants a CI step and not a
test file.

## `ls`: list the resources

```text
$ python stacks.py ls
orders-prod: 1 resource(s)
  Jobs  queue
```

Each line has the logical id, the type (its alias when it has one, `ManagedPolicy` for an `AWS::IAM::` type without one, and the full name otherwise; `-l` shows the full `AWS::SQS::Queue`) and the resource's own name when it is a literal (`QueueName`,
`FunctionName`, and `Name` for the types that call it that). `-t` keeps only some types: an alias
(`queue`, `lambda`, `role`, `lb`, `sg`, `table`, ...), a glob such as `'AWS::SQS::*'`, or the last
part of a type name, so `-t function` finds every `...::Function`.

The name and alias tables are short lists in `cfn_typed/cli.py` (`_NAME_PROPERTY` and `_ALIASES`).
A type with a blank name is a missing entry, and a pull request that adds it is welcome.

## Exit status

| Status | Meaning |
| --- | --- |
| 0 | everything is fine |
| 1 | `check` found problems, or `diff` found a difference or a missing file |
| 2 | bad usage, such as `emit` with several stacks and no `-o` |
